# Технічний звіт та покроковий опис: Simple Weather App

Цей документ містить детальний технічний розбір розробки погодного додатку на основі посібника `Technical Tutorial Step-by-Step Guide.md`. Тут пояснено не лише **що** було зроблено, а й **як** та **чому** працюють окремі механізми під капотом (JavaScript, API, DOM, CSS та Git).

---

## 1. Загальна концепція та архітектура додатку

Додаток побудовано за клієнтською моделлю (**Client-Side Rendering**) без власного сервера. Усі запити надсилаються напряму з браузера користувача до публічного сервісу **Open-Meteo**.

### Як взаємодіє додаток з API:
1. **Open-Meteo Geocoding API** — приймає назву міста (наприклад, `Brighton` або `Lewes`) і повертає географічні координати (`latitude`, `longitude`).
2. **Open-Meteo Weather Forecast API** — приймає координати та перелік бажаних параметрів погоди (`temperature_2m`, `weather_code`, `wind_speed_10m`), повертаючи актуальний прогноз у форматі **JSON**.
3. **Браузер (JavaScript)** — розбирає отриманий JSON та оновлює елементи інтерфейсу (DOM) без перезавантаження сторінки.

## 2. Детальний технічний розбір по етапах (Stages 1 – 5)

### Етап 1: Налаштування та конфігурація API (Stage 1)
- **Гілка Git:** `stage-1`

#### Що було зроблено:
- Створено початкову структуру HTML-сторінки.
- Оголошено об'єкт налаштувань `CONFIG`.
- Створено функцію `buildUrl()`.
- Виведено назву міста та клікабельне посилання на API.

#### Технічні деталі та пояснення:
1. **Об'єкт `CONFIG`:**
   ```javascript
   const CONFIG = {
     town: "Brighton",
     latitude: 50.8284,
     longitude: -0.1395
   };
   ```
   *Чому це важливо:* Збереження змінних даних в одному місці запобігає «магічним числам» у коді. Якщо потрібно змінити координати або додати API-ключ у майбутньому, ми змінюємо лише один об'єкт, а не шукаємо значення по всьому проекту.
2. **Формування URL через конкатенацію рядків (`+`):**
   ```javascript
   function buildUrl() {
     return "https://api.open-meteo.com/v1/forecast" +
       "?latitude=" + CONFIG.latitude +
       "&longitude=" + CONFIG.longitude +
       "&current=temperature_2m,weather_code,wind_speed_10m" +
       "&timezone=Europe%2FLondon";
   }
   ```
   *Як це працює:* Знак `?` позначає початок параметрів запиту (**Query String**), а знаки `&` розділяють окремі пари `ключ=значення`. Рядок `%2F` у параметрі таймзони — це закодований символ слеша (`/`), необхідний для коректної передачі в URL.
3. **Безпека посилань (`rel="noopener noreferrer"`):**
   У тегу `<a target="_blank">` атрибути `noopener` та `noreferrer` захищають від уразливості **Tabnabbing** (коли відкрита вкладка може отримати доступ до об'єкта `window.opener` початкової сторінки).

### Етап 2: Отримання та виведення сирих даних (Stage 2)
- **Гілка Git:** `stage-2`

#### Що було зроблено:
- Додано асинхронну функцію `loadWeather()`.
- Інтегровано `fetch` API.
- Виведено сирий JSON у тег `<pre id="raw-json">`.

#### Технічні деталі та пояснення:
1. **Асинхронність (`async / await`):**
   ```javascript
   async function loadWeather() {
     const response = await fetch(url);
     const data = await response.json();
   }
   ```
   *Як це працює під капотом:*
   - Мережевий запит займає певний час (зазвичай 50–300 мс). Браузер працює в одному головному потоці (Single Thread). Якби ми робили синхронний запит, інтерфейс повністю "завис" би на час очікування.
   - Ключове слово `async` вказує, що функція повертає **Promise** (обіцянку отримати результат у майбутньому).
   - `await` тимчасово призупиняє виконання коду всередині цієї функції, поки не прийде відповідь, не блокуючи при цьому решту сторінки.
2. **Двоетапне читання відповіді:**
   - `fetch(url)` повертає об'єкт заголовків та статусу відповіді (`Response`).
   - `await response.json()` окремо зчитує тіло відповіді та перетворює рядок JSON у звичайний JavaScript-об'єкт.
3. **Тег `<pre>` та метод `JSON.stringify`:**
   ```javascript
   rawJsonElement.textContent = JSON.stringify(data, null, 2);
   ```
   - Тег `<pre>` (preformatted) зберігає всі пробіли, відступи та переноси рядків.
   - Третій аргумент `2` у `JSON.stringify` задає кількість пробілів для красивого форматування (Pretty Print).

### Етап 3: Парсинг та обробка помилок (Stage 3)
- **Гілка Git:** `stage-3`

#### Що було зроблено:
- Створено розмітку зі спанами для окремих показників погоди.
- Створено функцію `showWeather(data)`.
- Додано захист від збоїв за допомогою блоку `try...catch`.

#### Технічні деталі та пояснення:
1. **Парсинг структури JSON:**
   Open-Meteo повертає вкладений об'єкт. Ми дістаємо конкретні поля через точкову нотацію:
   - `data.current.temperature_2m` — поточна температура на висоті 2 метри від землі.
   - `data.current.weather_code` — числовий код стану погоди за стандартом WMO (Всесвітня метеорологічна організація).
   - `data.current.time` — дата та час зняття показників у форматі ISO 8601 (`YYYY-MM-DDTHH:MM`).
2. **Безпечна маніпуляція DOM через `textContent`:**
   Ми використовуємо `element.textContent = ...` замість `element.innerHTML`. Це захищає від атак типу **XSS (Cross-Site Scripting)**, оскільки текст вставляється безпечно, без інтерпретації HTML-тегів.
3. **Конструкція `try...catch` та статус `response.ok`:**
   ```javascript
   try {
     const response = await fetch(url);
     if (!response.ok) {
       throw new Error("HTTP error " + response.status);
     }
     const data = await response.json();
     showWeather(data);
   } catch (error) {
     errorElement.textContent = "Could not load the weather.";
   }
   ```
   *Важливий нюанс `fetch`:* `fetch` не генерує помилку (`catch`), якщо сервер відповів помилкою на кшталт 404 або 500. Він вважає такий запит успішно виконаним мережевим обміном. Тому ми обов'язково перевіряємо властивість `response.ok` (яка повертає `true` для статусів 200–299) і вручну кидаємо помилку через `throw new Error()`. Якщо ж зникне інтернет взагалі, `fetch` сам перейде в блок `catch`.

### Етап 4: Форматування даних та кнопка оновлення (Stage 4)
- **Гілка Git:** `stage-4`

#### Що було зроблено:
- Додано кнопку `"Refresh data"`.
- Створено функцію форматування дати `formatDate()`.
- Створено функцію розшифровки коду погоди `describeWeather()`.
- Додано позначення градусів `°C`.

#### Технічні деталі та пояснення:
1. **Алгоритм `formatDate(dateString)`:**
   Рядок з API: `"2026-10-28T12:45"`.
   ```javascript
   function formatDate(dateString) {
     const parts = dateString.split("T");        // ["2026-10-28", "12:45"]
     const dateParts = parts[0].split("-");      // ["2026", "10", "28"]
     const timePart = parts[1];                  // "12:45"
     return dateParts[2] + "/" + dateParts[1] + "/" + dateParts[0] + " " + timePart;
   }
   ```
   *Результат:* `"28/10/2026 12:45"` (стандартний європейський формат `DD/MM/YYYY HH:MM`). Метод `.split(розділювач)` розбиває рядок на масив підрядків.
2. **Таблиця кодів WMO у `describeWeather(code)`:**
   Стандарт Всесвітньої метеорологічної організації використовує числові коди. Ми групуємо їх за допомогою операторів порівняння:
   - `0` → `Clear sky` (Ясне небо).
   - `1..3` → `Cloudy` (Хмарно: переважно ясно, мінлива хмарність, суцільна хмарність).
   - `45..48` → `Fog` (Туман або паморозь).
   - `51..67` → `Rain` (Мряка або дощ різної інтенсивності).
   - `71..77` → `Snow` (Снігопад).
   - `80..82` → `Rain showers` (Зливовий дощ).
   - `95+` → `Thunderstorm` (Гроза з градом чи без).
3. **Слухач подій (`Event Listener`):**
   ```javascript
   document.getElementById("refresh-button").addEventListener("click", loadWeather);
   ```
   Ми передаємо функцію `loadWeather` як **callback** (посилання на функцію), без круглих дужок `()`. Це означає: "викликати цю функцію тільки тоді, коли користувач натисне кнопку".

### Етап 5: Додаткові покращення та фінальний вигляд (Stage 5 — Extras)
- **Гілка Git:** `stage-5`

#### Що було зроблено:
- Розподілено файли за папками: `/assets/css/styles.css` та `/assets/js/app.js`.
- Створено сучасний інтерфейс з карткою (Card UI), тінню та плавними скругленнями.
- Реалізовано функцію `weatherIcon(code)` для показу емодзі та зміни фону сторінки.
- Створено повноцінний пошук будь-якого міста світу через Geocoding API.

#### Технічні деталі та пояснення:
1. **Принцип розділення обов'язків (Separation of Concerns):**
   - `index.html` — відповідає виключно за семантику та структуру (контейнери, заголовки, форми).
   - `assets/css/styles.css` — відповідає виключно за зовнішній вигляд та анімації.
   - `assets/js/app.js` — відповідає за бізнес-логіку та взаємодію з API.
2. **Двоетапний пошук міста (`searchTown`):**
   Користувач вводить назву міста (наприклад, `Lewes` або `Kyiv`).
   ```javascript
   const geocodeUrl = "https://geocoding-api.open-meteo.com/v1/search?name=" +
     encodeURIComponent(trimmedName) +
     "&count=1";
   ```
   - `encodeURIComponent()` обов'язковий: він перетворює спецсимволи та кирилицю у безпечний для URL формат.
   - Якщо масив `data.results` не порожній, ми оновлюємо `CONFIG`:
     ```javascript
     CONFIG.town = firstResult.name + (firstResult.country ? ", " + firstResult.country_code : "");
     CONFIG.latitude = firstResult.latitude;
     CONFIG.longitude = firstResult.longitude;
     ```
   - Після цього викликаємо `loadWeather()`, який робить запит до другого API з новими координатами.
3. **Динамічний фон та емодзі (`weatherIcon`):**
   Залежно від коду погоди змінюється значення `document.body.style.background` на відповідний градієнт (сонячний жовто-помаранчевий для ясного неба, приглушений синій для дощу, нейтральний сірий для хмар чи туману). Завдяки CSS-властивості `transition: background 0.4s ease` зміна кольору відбувається плавно, без різких стрибків.
4. **CSS Glassmorphism та анімація:**
   - `backdrop-filter: blur(12px)` створює ефект матового напівпрозорого скла для картки.
   - `@keyframes floatEmoji` створює плавне вертикальне коливання іконки погоди для відчуття живої інтерактивності.
